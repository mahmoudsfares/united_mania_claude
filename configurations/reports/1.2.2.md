# 1.2.2 — Strings, error messages, route names, json keys

## What was asked

Create the four constants files in `core/utils/` that hold every visible label, every user-facing
error message, the two route names, and every key read from the API response — so no later
subtask ever needs to hardcode one of these values.

## What changed

- `lib/core/utils/app_strings.dart` — new. `AppStrings`: `appTitle` ("United Mania"), `homeTitle`
  (the feed screen's heading, "Manchester United News"), `retry`, `readFullArticle`, and
  `noArticles` (the empty-list message referenced directly in `news_feed.md` §4).
- `lib/core/utils/app_error_messages.dart` — new. `AppErrorMessages`: `noInternet`, `timeout`,
  `invalidApiKey`, `rateLimited`, `serverError`, `generic` (the six failure categories from
  `news_feed.md` §2), plus `noArticleLink` and `couldNotOpenLink` for the details screen's link
  failures, named exactly as `news_details.md` §4 references them.
- `lib/core/utils/routes.dart` — new. `Routes.home` (`/`) and `Routes.newsDetails`
  (`/news-details`).
- `lib/core/utils/json_keys.dart` — new. `JsonKeys`: the twelve keys the API response uses —
  `status`, `articles`, `source`, `id`, `name`, `author`, `title`, `description`, `url`,
  `urlToImage`, `publishedAt`, `content`.

All four follow the private-constructor, static-const-only pattern already used by `AppColors`
(1.2.1). Nothing in `lib/` references these yet — they get wired in by the subtasks that build the
screens, repo, and network layer.

## What was tested

- Four new test files under `test/core/utils/`, written first and confirmed failing (the
  referenced classes did not exist) before the four files above were created:
  - `app_strings_test.dart` — every `AppStrings` constant is non-empty.
  - `app_error_messages_test.dart` — every `AppErrorMessages` constant is non-empty.
  - `routes_test.dart` — both route constants are non-empty, and `home` differs from
    `newsDetails`.
  - `json_keys_test.dart` — every `JsonKeys` constant is non-empty.
- `flutter analyze` — no issues found.
- `flutter test` — full suite passing.

## Anything left open

Nothing for this subtask. These constants are not yet referenced anywhere in `lib/` — that wiring
happens in the subtasks that need each value (screens, `NetworkErrorHandler`, `ApiEndpoints`, the
router).
