# 1.1.1 — Dependencies, lints, test harness

## What was asked

Get the empty Flutter project ready to build and test under the project rules: add the packages the
app will need, make the analyzer enforce the explicit-type rule, throw away the sample counter app
that `flutter create` left behind, and prove the whole thing runs with one test on the machine and
one test on a real device.

## What changed

**Packages added** (`pubspec.yaml`)

- For the app: `dio` 5.11.1 (network), `flutter_bloc` 9.1.1 (cubits), `equatable` 3.0.0 (value
  comparison), `intl` 0.20.3 (date formatting), `url_launcher` 6.3.2 (opening articles in the
  browser).
- For the tests: `bloc_test` 10.0.0, `mocktail` 1.0.5, `http_mock_adapter` 0.6.1, and
  `integration_test` from the Flutter SDK.

**Analyzer** (`analysis_options.yaml`)

- Turned on `always_specify_types`. The rule "every variable must have a written-out type" is now
  checked by the build instead of by eye, so a missing type is an error nobody has to spot in
  review. Left a note in the file that `omit_local_variable_types` is the opposite rule and must
  never be switched on beside it.

**Sample code removed**

- `lib/main.dart` — the counter demo is gone. What is left is the smallest app that can exist: it
  starts, and shows an empty screen. No colours and no navigation yet; those arrive in 1.2.1 and
  2.5.1.
- `test/widget_test.dart` — deleted. It only tested the counter demo.

**Assets**

- Created `assets/images/article_placeholder.png` — a dark red 640x360 image shown later wherever a
  news article has no picture, which the live API returns often. Registered `assets/images/` in
  `pubspec.yaml`.

**Tests added**

- `test/app_smoke_test.dart` — the app builds and does not throw.
- `integration_test/app_smoke_test.dart` — the app launches on a real device and does not crash.

## What was tested

Both tests were written before the app existed and were watched failing first, then made to pass.

- `flutter analyze` — **no issues found**, with the new strict type rule switched on.
- `flutter test` — **1 test, passed**.
- `flutter test integration_test` — **1 test, passed**, on an Android 14 (API 34) emulator. The
  first Android build took about ten minutes; later runs reuse that work and are far quicker.

## Anything left open

**One problem on this machine, and it is not caused by the project.**

Flutter's package folder, `C:\Users\msaeed\AppData\Local\Pub\Cache`, refuses to let any program
rename a file inside it — Windows answers "the handle is invalid". Downloading packages is mostly
renaming, so `flutter pub get` fails there every time. This was checked directly: creating a folder
inside the cache and renaming it fails in PowerShell too, so it is nothing to do with Flutter. The
folder is owned by the right user and has no blocking permissions, which points at security
software on the machine intercepting the operation.

**What was done about it.** A temporary package folder at `D:\pub_cache` was used to get this
subtask finished — everything downloaded and every test passed first time. That proved the packages
and the code are fine and the fault is purely the folder on C:.

**That workaround has since been removed**, at the owner's request, so the machine is back exactly
as it was: `D:\pub_cache` is deleted, and no `PUB_CACHE` setting was ever saved to the machine (it
only ever existed inside the individual commands that were run). The project's `.dart_tool` folder
was cleared too, because it still held package paths pointing at the deleted D: folder.

**What this means for the next person to open the project.** The packages are listed in
`pubspec.yaml` but are not downloaded right now. `flutter pub get` has to succeed once before
anything will build, and it will keep failing until the cache folder on C: is repaired. The owner
is handling that.

Nothing in this subtask's code is affected. `pubspec.yaml`, `analysis_options.yaml`, `lib/`,
`test/`, `integration_test/` and the placeholder image are all final, and all of them passed on the
temporary cache before it was removed.
