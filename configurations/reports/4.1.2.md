# 4.1.2 — Drop removed articles

## What was asked

NewsAPI returns placeholder entries whose `title`, `description`, and `content` are the literal
string `"[Removed]"`. Filter them out in both repos, in one place, before the list reaches the
cubit.

## What changed

- New file `lib/features/news_feed/business_logic/removed_articles_filter.dart`:
  `RemovedArticlesFilter`, a static-method class (same shape as `DateFormatter`) with
  `removedPlaceholder = '[Removed]'` and `dropRemoved(List<Article>)`, which keeps only the
  articles whose `title` isn't that literal string. This is the "one place" the subtask asked for.
- `NewsFeedRepo.getNews()` and `NewsFeedMockRepo.getNews()` both now pass their parsed article list
  through `RemovedArticlesFilter.dropRemoved(...)` before wrapping it in `StateResource.success` —
  one function, called from both repos, so the filtering rule exists in exactly one place.
- `test/features/news_feed/business_logic/removed_articles_filter_test.dart` (new): three articles
  where one is `"[Removed]"` yields two; a list of only removed articles yields an empty list;
  a list with nothing removed is returned unchanged. Its data comes from
  `NewsFeedMockRepo.successResponseBody`'s existing fixture, parsed through `Article.fromJson` —
  no hand-built payload.
- `news_feed_mock_repo_test.dart`: page 1 is now asserted at nine articles (was ten), plus a check
  that none of them carry the removed title. The separate `successResponseBody` group, which parses
  the raw fixture directly rather than going through `getNews()`, is unchanged at ten — that's the
  fixture's own shape (it still includes the removed entry on purpose, per `news_feed.md` §5), not
  what the repo hands back.
- `news_feed_repo_test.dart`: scenario 3 ("parses every article in the mock repo payload") now
  compares against the fixture filtered the same way the repo filters it, instead of a raw 1:1
  index match — the unfiltered fixture has the removed entry at index 2, which used to line up
  with the response but no longer does once it's dropped.
- `news_feed_cubit_test.dart`: the "with the real `NewsFeedMockRepo`" group's article-count
  assertions corrected from 10 → 9 (page one) and 14 → 13 (after page two).
- `integration_test/features/news_feed/news_feed_screen_test.dart`: card-count assertions corrected
  the same way, 10 → 9 and 14 → 13, across the launch, retry, and pull-to-refresh tests.
- `configurations/features_description/news_feed.md`: added a line under "4. Screen behaviour"
  documenting the drop-removed rule, and fixed the now-stale 10/14 counts in the "Tests" and
  "End-to-end" sections.
