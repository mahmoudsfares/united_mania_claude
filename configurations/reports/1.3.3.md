# 1.3.3 — `ApiEndpoints`, `DioInterceptor`, `AppDioClient`

## What was asked

The one door all HTTP traffic goes through: the endpoint constants, an interceptor that attaches
the api key and logs in debug builds, and a thin Dio wrapper that repos will call in Sprint 2.

Before writing any code, one open decision had to be settled: the work breakdown flagged the api
key's storage (hardcoded constant vs. `--dart-define`) as undecided. You chose the hardcoded
constant and provided the real NewsAPI key, so that is what got built.

## What changed

- `lib/core/networking/api_endpoints.dart` — new. `static const String` only:
  - `baseUrl`, `everything` — the base URL and path from `news_feed.md` §2.
  - `apiKey` — the real key, hardcoded per your decision.
  - `apiKeyQueryParam` — the query parameter name (`'apiKey'`) the interceptor attaches it under.
    Added beyond the subtask's literal list because the interceptor needs that map key too, and
    CLAUDE.md §4 forbids a hardcoded map key anywhere outside its constants file.
  - `q`, `sortBy`, `language` — the query values from the spec.
- `lib/core/networking/dio_interceptor.dart` — new. `DioInterceptor extends Interceptor`:
  `onRequest` attaches `apiKeyQueryParam: apiKey` to every request's query parameters; both
  `onRequest` and `onResponse` log via `debugPrint`, guarded by `kDebugMode` so nothing logs in
  release builds.
- `lib/core/networking/app_dio_client.dart` — new. `AppDioClient` wraps a `Dio` (creates one if
  none is injected), setting `baseUrl`, a 30-second connect/receive timeout, and adding
  `DioInterceptor`. `get(path, {queryParameters})` is a plain pass-through to `_dio.get` — it
  catches nothing, matching "repos do that." The constructor takes an optional `Dio` so tests can
  attach a mock adapter to the exact instance it configures.
- `configurations/features_description/work_breakdown.md` (Open decisions #2) and `news_feed.md`
  §3.5 — updated from "worth deciding" to "decided in 1.3.3," recording the hardcoded choice.

## What was tested

- `test/core/networking/api_endpoints_test.dart` — exact values for `baseUrl`, `everything`,
  `apiKeyQueryParam`, `q`, `sortBy`, `language`; `apiKey` is only checked for non-emptiness, so the
  real key is not duplicated into a test file.
- `test/core/networking/dio_interceptor_test.dart` — calls `onRequest` directly with a bare
  `RequestOptions` and `RequestInterceptorHandler`, and asserts the api key lands in
  `queryParameters`.
- `test/core/networking/app_dio_client_test.dart` — using `http_mock_adapter`'s `DioAdapter`
  attached to the same `Dio` instance the client configures: a 200 returns the decoded body; a
  request matches only when the mock expects the real api key in its query parameters (proving the
  interceptor is wired in, not just present in isolation); a 401 and a timeout (via
  `server.throws`) both propagate as `DioException` rather than being swallowed.
  `http_mock_adapter`'s mock-server callback type (`MockServer`) is not exported from its public
  API, so those four callbacks are left for Dart to infer and the `always_specify_types` lint is
  silenced line by line with a comment explaining why — importing the package's internal `src/`
  path to name the type was judged more fragile than a documented, narrow lint exception.
- Confirmed the fail-first step for real: the three new `lib/` files were moved aside, you ran
  `flutter test` and got the expected compile errors, then they were restored.
- `flutter analyze` — no issues found (run twice: once catching the undefined `MockServer`
  annotation, fixed, then clean).
- `flutter test` — full suite passing (confirmed by you).

## Anything left open
