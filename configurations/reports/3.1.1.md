# 3.1.1 — Navigation and the details route

## What was asked

Tapping a card on the feed should open a details screen showing that article. This needed a
`Routes.newsDetails` case in the router (reading the `Article` from `settings.arguments`, falling
back to the route-not-found screen for a missing or wrong-typed argument), a title-only
`NewsDetailsScreen`, and the feed card's tap wired to push the new route.

## What changed

- `lib/features/news_details/news_details_screen.dart` — new. `NewsDetailsScreen`, a
  `StatelessWidget` taking an `Article`, showing just its title. No cubit yet — nothing on this
  screen is asynchronous until 3.1.3.
- `lib/core/routing/app_router.dart` — added the `Routes.newsDetails` case: reads
  `settings.arguments`, and if it isn't an `Article`, falls through to the same route-not-found
  screen the `default` case already used. That screen is now built by one shared private helper,
  `_routeNotFound()`, instead of being duplicated between the two call sites.
- `lib/features/news_feed/news_feed_screen.dart` — the card's `onTap` now calls
  `Navigator.pushNamed(context, Routes.newsDetails, arguments: article)` instead of doing nothing.
- Tests: `test/features/news_details/news_details_screen_test.dart` (new — renders the given
  article's title), `test/core/routing/app_router_test.dart` (extended — a valid `Article` argument
  builds `NewsDetailsScreen` for that article; a missing argument and a wrong-typed argument both
  show route-not-found), `integration_test/features/news_details/news_details_screen_test.dart`
  (new — tap the first card, land on details showing that article's title, back returns to the
  feed).

## What was tested

- The end-to-end test checks the article's title with `find.descendant(of:
  find.byType(NewsDetailsScreen), matching: find.text(...))` rather than a bare `find.text(...)`.
  `MaterialPageRoute` keeps the previous route mounted (offstage) after a push, so a plain text
  search could in principle match the same title still sitting in the feed's card behind it;
  scoping to the details screen rules that out regardless.
- Confirmed by you: `flutter test` and
  `flutter test integration_test/features/news_details/news_details_screen_test.dart`, both green.
- `flutter analyze` — no issues found (run by me).
