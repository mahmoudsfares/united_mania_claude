# 2.5.2 — The article card

## What was asked

Replace the feed's plain title-only rows with a real card: the image via `AppNetworkImage`, the
title, and the source name with the date from `DateFormatter`, with a null `source.name` (or a
null `source` entirely) not leaving a blank row. The card stays a private widget inside
`news_feed_screen.dart` — no per-feature `widgets/` directory exists — and gets a real tap target
that does nothing yet, since navigation arrives in 3.1.1.

## What changed

- `lib/features/news_feed/news_feed_screen.dart` — `itemBuilder` now returns a private
  `_ArticleCard` instead of a bare `ListTile`. The card is a `Card` wrapping an `InkWell` (a real,
  if currently no-op, tap target) containing a `Row`: an 80×80 `AppNetworkImage` thumbnail
  (clipped to rounded corners), then the title (up to two lines, ellipsized) and, only when it has
  content, a subtitle line joining `source.name` and the formatted `publishedAt` date. The subtitle
  is built by filtering out whichever of the two is null/empty before joining, so a null source
  with a date shows just the date (no stray leading separator), and a null source with no date
  renders no subtitle line at all.
- `lib/core/utils/app_strings.dart` — added `AppStrings.sourceDateSeparator` (`' · '`), the one new
  UI string this subtask needed.
- `test/core/utils/app_strings_test.dart` — asserts the new constant is non-empty.
- `test/features/news_feed/news_feed_screen_test.dart` — four new widget tests: the card renders
  title, source, and formatted date; a null image url shows the placeholder; a null source with a
  date shows just the date; a null source and a null date together leave no blank row (checked by
  counting `Text` descendants of the `Card` — exactly one, the title).
- `integration_test/features/news_feed/news_feed_screen_test.dart` — counts `Card` (and
  `AppNetworkImage`) instead of `ListTile`, per this subtask's "ten cards, each showing its title
  and image or placeholder" requirement. Its surface-size handling needed a real rework — see below.

## Design decisions this subtask needed

**Compact horizontal layout, not a full-width vertical image card.** A taller, Pinterest-style card
(image on top, text below) was the first instinct, but the existing "auto-fill" pagination test
(`automatically requests more pages while the list does not fill the screen`, from 2.5.1) depends on
real layout: with only 1–2 articles it asserts the list does *not* overflow the default test
viewport, so the screen keeps requesting pages on its own. A tall card risked flipping that
assertion for reasons having nothing to do with pagination logic. An 80×80 thumbnail next to the
text keeps each card close to the old `ListTile`'s footprint (roughly 116–120px), which turned out
to be safely within margin — the full suite confirms the auto-fill test still passes unchanged.

**The work breakdown's own wording has a loose thread.** Its "Do" section says "a null `author` or
`source.name` must not leave an empty line," but the card (per `news_feed.md` §4's explicit field
list) shows only `source.name` and the date — never `author`, which belongs to the details screen
instead. The Tests bullet only asks for a null-source case, not null-author, so the implementation
follows the canonical feed spec rather than that one sentence. Flagging this rather than silently
picking one reading.

**The end-to-end test broke in a way that pointed at a real product-behaviour interaction, not a
bad test.** The first pass just swapped `ListTile` for `Card` and enlarged the "fully visible"
surface so all 14 rows would fit for counting. Running it found 14 cards on the *very first*
assertion, where 10 were expected. Reason: at that generous surface height, 10 compact cards no
longer overflow the viewport, so `news_feed.md` §4's own "load another page automatically while the
screen isn't full" behaviour — the same mechanism the unit-level auto-fill test exercises — fired
before the first scroll ever happened. The fix was to stop treating "tall" as the resting state: the
surface now rests at the short, deliberately-overflowing size for the whole test (guaranteeing the
auto-fill trigger stays quiet until the test itself drags near the bottom), and only swings up to
the tall size for the instant it takes to count cards, then straight back down. The drag distance
was also widened from 600 to 3000 logical pixels — comfortably more than any plausible list height —
since the smaller figure no longer reliably reached the end once rows got taller than a bare
`ListTile`.

**An unrelated environment issue surfaced along the way.** One test run failed on
`INSTALL_FAILED_INSUFFICIENT_STORAGE` — the emulator's `/data` partition was 93% full (confirmed via
`adb shell df /data`), not a code problem. Wiping the emulator's data resolved it.
