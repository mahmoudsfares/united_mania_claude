# 4.1.1 — Pull to refresh

## What was asked

Wrap the feed list in a `RefreshIndicator` calling `getNews()`, so pulling down reloads page one.
The empty state must also be pullable, since otherwise an empty feed has no way to reload short of
restarting the app.

## What changed

- `lib/features/news_feed/news_feed_screen.dart`:
  - The success-with-articles branch now returns `RefreshIndicator(onRefresh: widget.cubit.getNews,
    child: ListView.builder(...))` instead of a bare `ListView.builder`. The list also gained
    `physics: const AlwaysScrollableScrollPhysics()`, which is what lets a short list (one that
    doesn't yet overflow the viewport) still register the pull gesture.
  - The empty-list branch now calls a new private method, `_buildEmptyState()`, instead of returning
    a bare `Center(child: Text(AppStrings.noArticles))`. `RefreshIndicator` needs a scrollable
    descendant to detect a pull at all — a `Center` alone never generates a scroll notification — so
    the message is now wrapped in a `ListView` (also with `AlwaysScrollableScrollPhysics`) holding one
    child. A `LayoutBuilder` + `ConstrainedBox(minHeight: constraints.maxHeight)` around that child
    keeps the message vertically centred in the viewport, matching how it looked before this
    subtask, rather than collapsing to the top of the screen the way an unconstrained single-child
    `ListView` would.
  - No changes to `NewsFeedCubit`/`NewsFeedState` — `getNews()` already resets to page one and emits
    loading → success/error, which is exactly `RefreshIndicator.onRefresh`'s `Future<void> Function()`
    shape, the same way it already served as `AppErrorView`'s `onRetry`.
- `test/features/news_feed/news_feed_screen_test.dart` — two new widget tests: pulling down over the
  empty state calls `getNews()` again (checked by counting page-1 requests), and pulling down over a
  populated list does the same. The populated-list case seeds 20 copies of the same fake article so
  the list already overflows the default test viewport on its own, keeping the auto-fill-while-short
  behaviour (2.5.1) out of the way of the count.
- `integration_test/features/news_feed/news_feed_screen_test.dart` — one new end-to-end test: launch
  the real app, pull down on the loaded list, see the full-screen loader appear (the same one
  `getNews()` already shows on first launch and on retry, since pulling to refresh re-triggers the
  exact same loading state), then see the ten cards again once the mock repo resolves.
