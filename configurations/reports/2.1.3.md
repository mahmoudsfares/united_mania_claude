# 2.1.3 — `NewsFeedMockRepo`

## What was asked

Build the feed's mock repo: same public shape as `NewsFeedRepo` (`getNews()` returning
`Future<StateResource<List<Article>>>`), a constructor flag that switches it to return an error
resource, and the feature's only fake payload, held as two `static const Map<String, dynamic>`
fixtures (`successResponseBody`, `errorResponseBody`) parsed through the real models. The ten fake
articles must include the three awkward cases from `news_feed.md` §5 (null `urlToImage`, a
`"[Removed]"` title, and a null `author` with a null `source.id`). This subtask also had to make
`news_feed_repo_test.dart` (written in 2.1.2 against a fixture that did not exist yet) compile and
pass.

## What changed

- `lib/features/news_feed/business_logic/news_feed_mock_repo.dart` — new. `NewsFeedMockRepo` takes
  one optional constructor flag, `returnError` (defaults to `false`), and is `const`-constructible.
  `getNews()` waits one second, then either returns
  `StateResource.error(errorResponseBody[JsonKeys.message])` or maps
  `successResponseBody[JsonKeys.articles]` through `Article.fromJson` and returns
  `StateResource.success(articles)` — the same parsing path a real 200 response would go through,
  so there is no second, hand-built copy of the data.
  - `successResponseBody` — `JsonKeys.status: 'ok'` plus `JsonKeys.articles`, ten article maps
    keyed entirely through `JsonKeys`. No `totalResults` key, per the subtask's own note that
    nothing reads it.
  - `errorResponseBody` — `JsonKeys.status: 'error'` plus a `JsonKeys.message` string.
  - The ten articles: one fully-populated Manchester United story (BBC Sport / Simon Stone) that
    also serves as `fixtureArticles.first` for the field-mutation helpers already written into
    `news_feed_repo_test.dart`; six more ordinary stories from different outlets (Sky Sports, ESPN,
    Goal.com, The Athletic, Daily Mail, Mirror Football) so the fixture reads like a real ten-item
    feed rather than one item repeated; and the three required awkward cases, each isolated to its
    own article so a test targeting one condition cannot accidentally pass because of another:
    - a Reuters item with `title`, `description`, and `content` all `"[Removed]"` — matching
      exactly what 4.1.2 says NewsAPI nulls for a removed article, no more. Its `author`, `source`,
      `url`, and `urlToImage` stay populated, so this case is not also the null-`urlToImage` or
      null-`author` case.
    - a Guardian item with `urlToImage: null` and everything else populated.
    - a Manchester Evening News item with `author: null` and `source.id: null` (its `source.name`
      is populated, matching `news_feed.md`'s note that `source.id` is "very often `null`" even
      when the outlet name is known).
- `test/features/news_feed/business_logic/news_feed_mock_repo_test.dart` — new. See below.
- No other file changed. `news_feed_repo_test.dart` (from 2.1.2) needed no edits — it now compiles
  and passes because `NewsFeedMockRepo.successResponseBody` / `errorResponseBody` exist with the
  shape it already expected.

## What was tested

- `test/features/news_feed/business_logic/news_feed_mock_repo_test.dart`:
  - the success path returns ten articles, timed with a `Stopwatch` to confirm the call actually
    waited at least one second rather than resolving immediately.
  - the `returnError: true` path returns an error resource whose message is exactly
    `errorResponseBody[JsonKeys.message]`, with `data` null.
  - `successResponseBody`'s articles parse through `Article.fromJson` without throwing.
  - the fixture contains an article with a null `urlToImage`, one with a `"[Removed]"` title, and
    one with both `author` and `source.id` null.
- Confirmed the fail-first step: you ran `flutter test test/features/news_feed/business_logic/`
  before `news_feed_mock_repo.dart` existed and got the expected failure — both the new test file
  and `news_feed_repo_test.dart` failed to compile, since both import the class.
- `flutter analyze` — no issues found. This was the first `flutter analyze` run in this
  environment, so it resolved dependencies as a side effect (no lockfile/`.dart_tool` yet); no
  explicit `flutter pub get` was run.
- `flutter test` (full suite) — all passing, confirmed by you. This is also the point where
  `news_feed_repo_test.dart`'s scenario checklist (written in 2.1.2 against this fixture) turned
  green for the first time.
