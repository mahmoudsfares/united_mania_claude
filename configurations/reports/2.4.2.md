# 2.4.2 — Paginate `NewsFeedRepo`

## What was asked

Make `NewsFeedRepo` request a specific page from the real API, the same way `NewsFeedMockRepo`
already serves fake data page by page (2.4.1): `getNews()` becomes `getNews({int page = 1})`, using
the same optional-parameter shape and for the same reason — it keeps compiling against
`NewsFeedCubit`'s existing zero-argument call unchanged until 2.4.3 paginates the cubit itself. Two
new query-parameter-name constants go on `ApiEndpoints` (`pageQueryParam`, `pageSizeQueryParam`),
and the page size value itself — an `int`, so it does not belong in `ApiEndpoints` under CLAUDE.md
§2 — becomes `static const int pageSize = 10` on `NewsFeedRepo`. Parsing and error handling stay
exactly as they were in 2.1.2.

## What changed

- `lib/core/networking/api_endpoints.dart` — added `static const String pageQueryParam = 'page'`
  and `static const String pageSizeQueryParam = 'pageSize'`, next to the other query-param-name
  constants.
- `lib/features/news_feed/business_logic/news_feed_repo.dart`:
  - `getNews()` → `getNews({int page = 1})`.
  - New `static const int pageSize = 10`.
  - The request's `queryParameters` map now also sends `ApiEndpoints.pageQueryParam: page` and
    `ApiEndpoints.pageSizeQueryParam: pageSize`, alongside the existing `q`/`sortBy`/`language`
    values. Nothing else in the method changed — parsing and the `catch` block routing to
    `networkErrorHandler` are untouched from 2.1.2.
- `test/core/networking/api_endpoints_test.dart` — added a test asserting the two new constants'
  string values.
- `test/features/news_feed/business_logic/news_feed_repo_test.dart`:
  - Every existing call site (`repo.getNews()`, six of them across the transport, 400, other-status,
    and malformed-200 scenario tests, several reached through the shared `expectError` helper) now
    calls `repo.getNews(page: 1)`. These scenarios are page-independent, so no other part of any of
    those tests changed.
  - Added `sends page and pageSize query values for page 1`, asserting the captured query map
    carries `page: 1` and `pageSize: NewsFeedRepo.pageSize`, stubbed against
    `NewsFeedMockRepo.successResponseBody`.
  - Added `forwards the requested page number rather than hardcoding it`, calling
    `getNews(page: 2)` stubbed against `NewsFeedMockRepo.successResponseBodyPageTwo` and asserting
    the captured query map carries `page: 2` — proving the page number is forwarded rather than a
    literal `1` baked into the method.
- No other file changed. `NewsFeedCubit` and its test needed no edits, confirmed by `flutter
  analyze` — a function with only optional parameters is still assignable wherever a zero-argument
  function is expected, exactly as reasoned in the 2.4.1 report.
