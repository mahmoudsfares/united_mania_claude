# 1.3.1 — StateResource<T>

## What was asked

A single generic result wrapper that every repo and cubit will use to represent init, loading,
success (with data), and error (with a message) states, comparable by value.

## What changed

- `lib/core/networking/state_resource.dart` — new. `StateResource<T>` extends `Equatable`, backed
  by a private `_Status` enum field (`init`, `loading`, `success`, `error`) set by four `const`
  named constructors: `.init()`, `.loading()`, `.success(value)`, `.error(message)`. Exposes
  `data` (`T?`) and `error` (`String?`), plus `isInit`, `isLoading`, `isSuccess`, `isError`
  getters. `success` sets `data` and leaves `error` null; `error` sets `error` and leaves `data`
  null. `props` includes the status, data, and error so two instances built the same way are
  equal.

## What was tested

- `test/core/networking/state_resource_test.dart`, written first and confirmed failing (no
  `state_resource.dart` existed yet) before the file above was created:
  - each constructor sets exactly one of the four `is*` getters to true;
  - `success` carries its data with a null error, `error` carries its message with a null data;
  - two instances built the same way are equal; instances built differently (different data,
    different message, or different constructor) are not.
- `flutter analyze` — no issues found.
- `flutter test` — full suite passing (confirmed by you).

## Anything left open

Nothing for this subtask. `StateResource` is not yet used anywhere — it gets wired in starting
with `NetworkErrorHandler` in 1.3.2.
